# Ficha de especificación por módulo

Usar esta ficha como complemento del template oficial Spec Kit; no reemplazar `spec.md`, `plan.md` y `tasks.md`.

## Identidad y alcance

Registrar nombre visible ARG, nombre técnico, circuito, objetivo y exclusiones.
Clasificar núcleo, presentación, gestión, puente, integración o rubro.
Registrar versión Community, revisión, licencia y dependencias propuestas.

## Usuario y recorrido mínimo

Definir actores, roles, problema cotidiano y resultado esperado.
Describir listado → ficha → documento → confirmación → consulta del origen.
Enumerar selecciones obligatorias, valores predeterminados y excepciones.
Conservar el orden común y explicar cada campo adicional.

## Documentos, hechos y dimensiones

Definir tipo, código corto, numeración, estados y transiciones.
Identificar efectos comerciales, físicos, contables, financieros y fiscales.
Registrar origen, destino, versión aceptada, aplicación parcial y reversión.
Definir hecho, granularidad, medidas, signos, fecha y dimensiones de cada indicador.
Explicar cómo evitar duplicaciones y conservar importes históricos.

## Contratos y seguridad

Identificar modelos nativos extendidos y justificar modelos nuevos.
Declarar puntos de extensión, permisos, compañías y ambientes.
Documentar concurrencia, idempotencia, adjuntos, importación y exportación cuando correspondan.
Para conectores, describir servicio, activación, datos compartidos y revocación desde Integraciones ARG.

## Entrega y documentación

Definir Ayuda → Tutoriales con lista YouTube, videos por tarea y manual correspondiente.
Registrar versiones compatibles, fecha de revisión, estado y tutorial sustituto cuando exista.
Evaluar impacto sobre tutoriales en cada cambio funcional o visual del módulo.
Conservar referencias en el catálogo central editable sin reinstalación de módulos.
Utilizar el acceso general Soporte ARG y su configuración única; evitar crear canales por módulo.

Redactar ejemplos de demostración sin datos reales.
Definir criterios de aceptación verificables y escenarios de QA posterior.
Registrar controles técnicos de instalación/arranque necesarios.
Entregar guía funcional, guía técnica, cambios, límites y recuperación.
Mantener pendientes de publicación y despliegue separados del desarrollo.
